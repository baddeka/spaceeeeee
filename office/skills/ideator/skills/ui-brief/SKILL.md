# Describe the interface for frontren

You decide what the interface is for and how it should feel. frontren decides how it looks: it proposes style directions, and the user picks one. Write the `ui` field in this shape, in under about 120 words:

1. **Screens:** each screen or view on its own line: its name and what the user does there. Most ideas need one to three.
2. **Main flow:** the steps of the most important thing a user does, from opening the app to the result, for example "paste text → pick a tone → copy the rewrite".
3. **States:** what the empty, loading and error states show, when the idea has them.
4. **Content:** the real kind of data on screen (names, prices, photos, charts), so the design is never built around placeholder text.
5. **Mood:** three words for how it should feel, such as "calm, focused, paper-like" or "loud, playful, arcade", and who it must suit (age, setting, device).
6. **Device:** phone first, desktop first, or both.

Rules:
- Name one thing that should make the interface memorable: an interaction, a visual idea or a small moment of delight. Without it, the result looks like every template.
- Do not pick exact colors, fonts or a component library; that is frontren's job, and the user chooses the style.
- Leave `ui` empty for an idea with no interface, such as a command-line tool or a library.
